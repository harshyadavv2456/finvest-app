PART 0 — THE HONEST STARTING POINT

Let me be completely direct about what we built and what it actually does.

What Problem Are We Solving?

The problem is NOT "where will the price go?"

The Real Problem: "Given current conditions, should capital be deployed, how much, and what's the downside?"

This is exactly how professional capital allocators think. Retail traders ask "what to buy?" — institutions ask "what's the risk-adjusted opportunity?"

What We Actually Built

We built a rules-based quantitative decision system that:

  1. Processes ~2,500 days of price data per stock
  2. Generates ~25 technical signals
  3. Classifies market regimes
  4. Computes probability distributions
  5. Calculates risk metrics (CVaR)
  6. Produces actionable decisions with position sizing
  7. Manages portfolio-level correlation risk

Runtime: ~20 seconds for 100 stocks.

What it is NOT:
  • Not a price predictor
  • Not an AI/ML system (we use rule-based logic)
  • Not a guarantee of anything
  • Not a replacement for human judgment

PART 3 — LAYER 2: REGIME ENGINE (THIS IS CRUCIAL)

Why Regimes Matter

Markets are non-stationary — the same signal means different things at different times.

Example:
• Momentum positive in ACCUMULATION = early trend, good
• Momentum positive in DISTRIBUTION = late, smart money exiting

If you ignore regimes, you're trading blind.

Our Six Regimes (What They Actually Mean)

Regime Real-World Meaning Characteristics
Accumulation Institutions quietly building positions Low volatility, range-bound, volume increasing
Markup Trend followers joining Higher highs, higher lows, sustained momentum
Distribution Smart money exiting Volatility expanding, failed breakouts
Markdown Sustained selling Lower highs, lower lows, momentum negative
Recovery Transition from weakness Volatility contracting, early stabilization
Panic Forced liquidation Extreme volatility, capitulation

How We Actually Classify (The Real Code)

# From layer2_regime_engine.py (simplified)
def classify_regime(prices_df):
    # Calculate features
    momentum_short = price_change_20d
    momentum_long = price_change_60d
    vol_ratio = vol_20d / vol_60d
    price_vs_sma = close / sma_50
    
    # Rule-based classification
    if vol_ratio > 1.5 and momentum_short < -0.10:
        return 'panic'
    elif momentum_short > 0.05 and momentum_long > 0.10:
        return 'markup'
    elif momentum_short < -0.05 and momentum_long < -0.10:
        return 'markdown'
    elif vol_ratio < 0.8 and abs(momentum_short) < 0.03:
        return 'accumulation'
    elif vol_ratio > 1.2 and momentum_short > 0 and price_vs_sma > 1.05:
        return 'distribution'
    else:
        return 'recovery'

Why rule-based, not ML:

  1. Transparent — you can explain every classification
  2. Robust — doesn't overfit to historical data
  3. Fast — computes in milliseconds
  4. No training data leakage
Honest limitation: Regime changes can be detected 1-5 days LATE. We're measuring history, not predicting the future.

Market vs Asset Regime

We classify TWO regimes:

  1. Asset regime: What phase is THIS stock in?
  2. Market regime: What phase is the OVERALL market in?

PART 4 — LAYER 3: SIGNAL EFFICACY (THE REAL EDGE)

The Key Question

"When this signal appeared IN THIS REGIME, what happened historically?"

This is WHERE THE EDGE COMES FROM.

Information Coefficient (IC)

The Formula:
IC = correlation(signal_value_t, forward_return_{t+20})

We calculate this for every signal, in every regime.

CVaR — THE MOST IMPORTANT RISK METRIC

The Formula:
CVaR_95 = average of returns in worst 5% of cases 
# The actual code
worst_5pct = returns_20d[returns_20d <= returns_20d.quantile(0.05)]
cvar_95 = float(worst_5pct.mean())
Example (AAPL):
• Worst 5% of 2,508 20-day periods = worst 125 periods
• Average return in those 125 periods = -15.2%
• CVaR_95 = -15.2%

What this means:
"In the worst 5% of scenarios historically, you would have lost at least 15.2% on average"
Why CVaR matters more than VaR:
• VaR tells you: "95% of the time, you won't lose more than X"
• CVaR tells you: "When you DO lose more than X, HERE'S how bad it gets"

CVaR measures tail risk — the catastrophic scenarios.

Regime-Conditional CVaR

# We adjust CVaR based on market conditions
cvar_95_normal = cvar_95 * 0.8    # Calm markets
cvar_95_stress = cvar_95 * 1.3    # Stressed markets
cvar_95_panic = cvar_95 * 2.0     # Crisis conditions
Why: In a panic, historical worst cases UNDERESTIMATE actual risk.

Conviction Calculation (The Real Code)

# From run_full_daily_intelligence.py
def calculate_conviction():
    base_conviction = 0.30  # Start at 30%
    
    # Return distribution adjustment
    if return_p50 > 0.02 and return_p90 > abs(return_p10):
        base_conviction += 0.20  # Upside > downside
    elif return_p50 < -0.02:
        base_conviction -= 0.10  # Negative median
    
    # Signal agreement adjustment
    if signal_agreement > 0.70:
        base_conviction += 0.15
    elif signal_agreement < 0.30:
        base_conviction -= 0.15
    
    # Regime adjustment
    if asset_regime in ['markup', 'accumulation']:
        base_conviction += 0.10
    elif asset_regime in ['markdown', 'panic']:
        base_conviction -= 0.20
    
    # Clip to [0, 1]
    return max(0, min(1.0, base_conviction))

# Actual code
def calculate_position_size(conviction, volatility, cvar):
    # Base: 6% max per position
    max_position = 0.06 * conviction
    
    # Volatility adjustment
    if volatility > 0.35:  # Extreme
        max_position *= 0.50
    elif volatility > 0.25:  # Elevated
        max_position *= 0.70
    
    # Risk budget constraint
    risk_budget = max_position * abs(cvar) / 0.15
    
    return min(max_position, risk_budget)
Example (AAPL): 
Conviction: 71%
Volatility: 16.4% (normal)
CVaR: -15.2%

max_position = 0.06 × 0.71 = 4.26%
vol_adjustment: × 1.0 (normal vol)
risk_budget = 4.26% × 15.2% / 15% = 4.3%

Final recommendation: 4.26%, scaled in 2 tranches
Key Insight: Position size is determined by RISK, not conviction alone.

PART 10 — LAYER 9: PORTFOLIO RISK (CORRELATION-AWARE)

This is where we go from stock-level to portfolio-level.

The Problem: Correlation

Scenario: You have 10 "INITIATE" stocks, all tech.

Problem: If tech crashes, ALL 10 crash together. Your "diversified" portfolio behaves like 1 concentrated bet.

Correlation Matrix

def compute_rolling_correlation(returns_dict, lookback=60):
    returns_df = pd.DataFrame(returns_dict)
    returns_df = returns_df.tail(lookback)
    corr_matrix = returns_df.corr()
    return corr_matrix

Effective Positions

The Formula:
Effective Positions = 1 / Σ(wᵢ²) 
def compute_effective_positions(weights):
    weights_arr = np.array(list(weights.values()))
    weights_arr = weights_arr / weights_arr.sum()  # Normalize
    hhi = np.sum(weights_arr ** 2)
    return 1.0 / hhi

Marginal Risk Contribution (MRC)

The Formula:
MRC_i = wᵢ × Σⱼ(wⱼ × σᵢ × σⱼ × ρᵢⱼ) 
def compute_marginal_risk_contribution(weights, volatilities, correlation_matrix):
    mrc = {}
    for ticker_i in weights:
        w_i = weights[ticker_i]
        sigma_i = volatilities[ticker_i]
        
        mrc_i = 0
        for ticker_j in weights:
            w_j = weights[ticker_j]
            sigma_j = volatilities[ticker_j]
            rho_ij = correlation_matrix.loc[ticker_i, ticker_j]
            
            mrc_i += w_j * sigma_i * sigma_j * rho_ij
        
        mrc[ticker_i] = w_i * mrc_i
    
    return mrc

PART 13 — WHAT CAN GO WRONG (HONEST)

1. Regime Detection Lag

Regimes are detected using PAST data. By the time we identify "panic," we're already IN the panic. 1-5 day lag is normal.

2. Historical Patterns May Not Repeat

Just because momentum worked in accumulation historically doesn't guarantee it works in the next accumulation. Markets evolve.

3. Data Quality Issues

Corporate actions (splits, dividends) can distort signals. We don't fully adjust for these.

4. Correlation Breakdown in Crises

During crashes, correlations spike to 1. Our 60-day rolling correlation won't see it coming.

5. No Real-Time Execution

This is an end-of-day analysis system, not a trading system. Actual execution would add slippage and timing issues.
